# Семь дефектов выпуска и сервиса

Обязательная таблица для сдачи сохранена в [defects.csv](defects.csv). Ниже — её версия для чтения. Все регрессионные тесты находятся в [tests/test_integration.py](tests/test_integration.py).

Общая команда запуска новых интеграционных тестов:

```bash
python3 -m unittest discover -s tests -p test_integration.py -v
```

Результаты исходного прототипа сохранены в [original-red.log](evidence/original-red.log), исправленного — в [fixed-green.log](evidence/fixed-green.log). В исходной версии перечисленные проверки падают, в исправленной — проходят.

## 1. Устаревший результат подготовки

- **Симптом:** после изменения содержимого входного файла по тому же пути используется старый кеш.
- **Причина:** ключ зависел только от пути, а не от байтов файла и настроек подготовки.
- **Исправление:** ключ строится из SHA-256 содержимого и канонического JSON настроек, включая версию токенизатора, шаблон, длину и версию кода.
- **Регрессионный тест:** `test_cache_recovery_and_changed_input` — проверяет восстановление после сбоя и инвалидацию при изменении входа.

## 2. Неполный или чужой отчёт допускается к выпуску

- **Симптом:** выпуск может пройти по незавершённому отчёту или отчёту другой модели.
- **Причина:** проверялась только истинность поля `passed`; например, строка `"false"` считается истинной.
- **Исправление:** проверяются полнота отчёта, настоящий boolean `True`, конечные метрики, идентификаторы, хеши и согласованность runtime.
- **Регрессионный тест:** `test_rejected_and_foreign_report_preserve_pointer` — проверяет отказ и неизменность прежнего указателя.

## 3. Указатель небезопасно записывается при ошибке

- **Симптом:** ошибка записи может повредить ранее принятую версию.
- **Причина:** JSON записывался непосредственно поверх целевого файла.
- **Исправление:** запись во временный файл рядом с целевым, `flush` и `fsync`, затем атомарный `os.replace`; временный файл удаляется при ошибке.
- **Регрессионный тест:** `test_failed_replace_keeps_pointer` — имитирует ошибку замены и проверяет сохранность прежних байтов. Исходный код не вызывает атомарную замену, поэтому этот тест на нём падает.

## 4. Повтор создаёт дубликаты выпуска

- **Симптом:** одинаковые запуски добавляют повторные события публикации.
- **Причина:** журнал пополнялся безусловно, без идентификатора выпуска и проверки предыдущих событий.
- **Исправление:** идентификатор учитывает manifest и решение допуска; повтор восстанавливает недостающее событие и не добавляет дубликат. Попытки ведутся отдельно от событий выпуска.
- **Регрессионный тест:** `test_recovery_after_pointer_and_repeat` — проверяет повтор и восстановление после сбоя между обновлением указателя и записью события.

## 5. Сервис сообщает о готовности до прогрева

- **Симптом:** `/ready` и `/generate` доступны до завершения прогрева.
- **Причина:** флаг готовности устанавливался сразу при создании состояния сервиса.
- **Исправление:** готовность устанавливается только после загрузки и прогрева; до этого запрос генерации получает 503.
- **Регрессионный тест:** `test_readiness` — проверяет состояние до и после прогрева.

## 6. Ответ содержит не фактически загруженную версию

- **Симптом:** после публикации B работающий на A сервис указывает в ответе B, хотя продолжает использовать A.
- **Причина:** идентификатор для ответа заново считывался из `accepted.json`, а не из загруженного backend.
- **Исправление:** `model_id` и `runtime_sha256` берутся из backend, загруженного при старте процесса.
- **Регрессионный тест:** `test_loaded_version_and_rollback` — проверяет A, публикацию B без перезапуска, загрузку B и откат к A через перезапуски.

## 7. Неверный запрос запускает вычисление

- **Симптом:** пустой prompt или недопустимый лимит доходят до backend.
- **Причина:** валидация отсутствовала до вызова генерации.
- **Исправление:** prompt и `max_new_tokens` проверяются до обращения к backend; неверный запрос получает 4xx.
- **Регрессионный тест:** `test_invalid_request_never_calls_backend` — сравнивает счётчик вызовов до и после некорректных запросов и проверяет один корректный вызов.
