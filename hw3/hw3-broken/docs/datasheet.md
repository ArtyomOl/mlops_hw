# Паспорт датасета: вопросы по статьям об NLP

## Назначение и источник

Набор предназначен для дообучения ассистента, который отвечает на вопрос о научной статье **только по приведённому фрагменту**. Язык исходных вопросов и ответов — английский. Тема для согласования с преподавателем: *ответы на вопросы по текстовым подтверждениям из статей об обработке естественного языка*.

Сырьё — [QASPER v0.3 от Allen Institute for AI](https://allenai.org/data/qasper), [официальный архив train/dev](https://qasper-dataset.s3.us-west-2.amazonaws.com/qasper-train-dev-v0.3.tgz), SHA-256 архива `a28fdf966db827bcee3d873107d6b6669864fb7ca8fbf73a192f5e39191bdb5a`. [Карточка набора](https://huggingface.co/datasets/allenai/qasper) указывает лицензию **CC BY 4.0**. При использовании данных необходимо указывать авторов QASPER; права на тексты отдельных научных статей могут отличаться. В git попадают только код, метрики и DVC-указатели; сами файлы источника и JSONL хранятся через DVC.

## Что сделано с источником

1. Выбраны только вопросы с аннотированным извлекаемым ответом (`extractive_spans`) и текстовым `evidence`. Отсутствующие в подтверждении фрагменты исключены. В v1 просмотрено 2 593 вопроса, 1 272 без подходящего извлекаемого ответа, 4 без текстового подтверждения и 21 с несовпадением фрагмента и подтверждения; записано 1 296.
2. Из каждой подходящей аннотации выбран кратчайший набор подтверждающих абзацев, содержащий **все** фрагменты ответа. Создан новый chat-пример: пять детерминированно выбираемых формулировок инструкции, заголовок статьи и подтверждение во входе, проверенный ответ на выходе. `id` — исходный ID вопроса, `topic` — ID статьи arXiv.
3. Применены схема `system → user → assistant`, фильтр длин, маскирование ПДн, точная дедупликация по нормализованному вопросу и MinHash/LSH near-dup с проверкой кандидатов точным Жаккаром. Для длинного контекста ключом дубля служит сам вопрос: общий абзац статьи не делает разные вопросы дублями.

В `v1` используется исходная часть train. `v2` добавляет исходную часть dev. Это **версии сырья**, а не финальные train/val/test: после объединения пайплайн строит собственный сплит по статьям. Исходный тест QASPER не используется.

## Сплит и ограничения

Группа сплита — целая статья (`topic` = arXiv ID), seed `42`, целевые доли 80/10/10. Статья целиком попадает в один сплит. После дедупликации отдельный гейт сравнивает **каждую пару** train/val/test по ID, нормализованному вопросу, статье и near-dup: все пересечения равны нулю. Порог near-dup при очистке и проверке одинаковый: `0.85`.

Набор покрывает только англоязычные статьи об NLP и только вопросы, на которые можно ответить по уже выбранному подтверждению. Он не учит искать нужный абзац в полной статье, отвечать на вопросы без ответа, работать с таблицами/изображениями или давать свободное объяснение. Ручная повторная проверка всех исходных аннотаций не выполнялась; автоматическая сверка гарантирует наличие выбранного фрагмента в подтверждении, но не научную истинность утверждения. MinHash/LSH — вероятностная проверка близости, поэтому нулевой счётчик не является доказательством отсутствия всех возможных семантических парафразов.

Воспроизведение: `uv sync`, затем `make source` (если источники ещё не восстановлены через `dvc pull`), `make v1`, `make v2`, `make check`. После фиксации обеих версий в истории сравнение выполняется через `dvc metrics diff`. Контрольные SHA-256 исходных JSON записаны в `scripts/fetch_source.py`.
