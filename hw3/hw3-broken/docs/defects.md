# Пять дефектов исходного пайплайна

## 1. Данные попадали в git

В исходном `.gitignore` не было `data/`. После `git add .` все JSONL могли стать частью истории. Добавлено игнорирование `data/`; исходные JSON и выходы стадий учитываются DVC, настроен локальный remote. Проверка: `git ls-files data/` возвращает **0** файлов, `dvc remote list` показывает `local`, `dvc push` для v1 отправил **7** объектов. Это исключает тяжёлые версии данных из коммитов, сохраняя их хэши в `.dvc` и `dvc.lock`.

## 2. Смена версии не запускала пересчёт

В `dvc.yaml` стадия `collect` не зависела от `collect.version` и файлов источника. DVC считал прежний `raw.jsonl` актуальным. Добавлены `params: collect` и зависимости от исходных JSON; выходной `metrics/collect.json` также объявлен метрикой. Контроль `make check`: при переключении v1 → v2 `raw` меняется с **1 296** до **1 940** строк, а MD5 `clean.jsonl` — с `13f06afc…` на `a4668453…`.

## 3. Случайный сплит давал контаминацию

Исходный `src/split.py` перемешивал отдельные строки, хотя несколько вопросов относятся к одной статье. Заменён на детерминированную раздачу целых групп по ID статьи; до неё выполняется дедупликация, а затем отдельная DVC-стадия `contamination` проверяет все три пары сплитов. На v2 получены **1 421 / 178 / 178** строк и **692 / 83 / 100** статей в train/val/test. Во всех парах — **0** пересечений по ID, вопросу, статье и near-dup.

## 4. Не хватало near-dup очистки

В исходном `src/clean.py` шаг near-dup был заглушкой. Сравнение полного пользовательского сообщения также плохо подходит для QASPER: длинное общее подтверждение могло скрыть или создать сходство вопросов. После точного сравнения запускается MinHash/LSH по выделенному вопросу; кандидаты проверяются точным Жаккаром, а тот же способ и порог применяются к контаминации. Контрольная пара из `make check` даёт **1** удалённый точный и **1** удалённый почти-дубль, несмотря на иное форматирование. Реальная пара с Жаккаром **0,80** сохраняется при пороге **0,85**. На v2 удалён **1** почти-дубль после **155** точных.

## 5. Гейт разнообразия только предупреждал

Исходный `src/diversity.py` печатал предупреждение, но завершался кодом 0, поэтому вырожденный набор шёл дальше. Теперь при нарушении порога стадия завершается ошибкой и печатает каждое нарушение отдельной строкой. Контрольный набор из **1 200** однотипных строк нарушает **4** порога и отклоняется. Реальная v2 проходит: **1 777** примеров, **5** системных промптов, **875** групп, доля крупнейшей **0,51%**, отношение p90/p10 длины ответа **19,0**.
